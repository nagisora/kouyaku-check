# 調査メモ（台帳の書き方）

点数、ランキング、「日本の健康度」は作りません。公開資料で主張と行動を対照し、**行動一致 / 公約実現 / ズレ / 不明** だけを付けます。4つは足し合わせません。

## 主張の書き方

成功条件が読める主張を優先します。

- **hard**: 数値、期限、または名前のある立法・制度・人事が主張に含まれる。
- **soft**: 「追及する」「議論する」「進める」など、測れる成功条件がない姿勢・議論。

soft も載せてよいですが、必ず `claim_kind: soft` を付けます。行動一致だけを soft で埋めた台帳は、検証が警告します（CI は落とさない）。

## ラベル

| ラベル   | 使うとき                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 行動一致 | 発言・委員会質疑・質問主意書・賛成者・会派態度など、主張の**過程**には沿うが、成功条件はまだ満たしていない。 |
| 公約実現 | 法律の成立、具体的な政策結果、人事の設置など、主張の成功条件が**実際に**満たされた。                         |
| ズレ     | 公開資料上、主張と行動が食い違う。                                                                           |
| 不明     | 一括法案、資料不足、対応が判断できない。                                                                     |

公約実現は膨らませません。賛成者・共同提出・質疑は、notes が成立や数値達成を示さない限り行動一致です。法案の提出も過程です。

## 任意フィールド

分かるときだけ付けます。分からなければ省略します。

- `agency_capacity`: `individual`（本人） / `caucus_or_party`（会派・党） / `cabinet_or_executive`（内閣・行政） / `unknown`
- `agency_actor`: 誰が動いたかの短い自由記述
- `voting_method`: 表決のときだけ。`named_rollcall` / `pushbutton` / `standing_or_voice` / `no_objection` / `unknown`
- `horizon_status`: `achieved` / `in_flight` / `truncated_dissolution` / `horizon_not_reached` / `not_applicable`

## やってはいけないこと

- 行動一致と公約実現を「一致」に戻して合算する。
- 行動一致が多いことを国や内閣の成功と読む。
- 与党・内閣と野党の件数をそのまま比べる。
- 信頼スコアや偏差値を足す。
